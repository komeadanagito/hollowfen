## 1. 整体游戏愿景（背景）

Hollowfen 是一款 **2D 横版类银河战士恶魔城（Metroidvania）** 游戏，目标是**完整可发布作品**，长期分阶段构建。

- **气质**：黑暗、阴郁的沼泽世界（空洞骑士 / 鲜血之夜风格）。
- **核心机制**：多个可玩角色，**Trine 式瞬间切换**——同一时间只控制一个角色，按键瞬切。选对角色既是战斗也是解谜的关键。
- **战斗**：每个角色有独立特性，分近战 / 远程。
- **解谜**：嵌在探索流程中，常需切换角色来解。

### 分阶段路线图

| 阶段 | 内容 | 目的 |
|------|------|------|
| **阶段 0：垂直切片**（本文档） | 1 测试房间 + 2 角色 + 切换 + 基础移动/战斗 + 1 谜题 | 验证核心乐趣 |
| 阶段 1：架构加固 | 角色/能力系统、输入、相机、存档、房间切换骨架 | 可扩展地基 |
| 阶段 2：战斗深度 | 更多敌人、AI、受击反馈、死亡重生 | 战斗扎实 |
| 阶段 3：解谜系统 | 可复用机关库、角色专属交互 | 解谜扎实 |
| 阶段 4：世界结构 | 互联地图、能力门禁、地图 UI | Metroidvania 骨架 |
| 阶段 5：内容与打磨 | 美术、音效、关卡、剧情、Boss、菜单 | 成品化 |

每个阶段单独走「设计 → 计划 → 实现」。本文档只覆盖**阶段 0**。

## 2. 阶段 0 目标

做出一个**能玩的测试房间**，验证「切换角色打怪 + 解谜」的核心乐趣。

**架构方案：方案 A — 附身 / 管理器模型**
每个角色是完全独立的场景（自带移动、战斗、贴图、血量）。一个 `PartyManager` 持有所有角色，只让当前激活角色运行/显示，转发输入，相机跟随激活角色。切换 = 在同一世界坐标换激活角色。借鉴少量组合思想（Health、Hurtbox 做成可复用子节点），整体保持场景化结构。

---

## 3. 场景结构

```
TestRoom.tscn                  ← 关卡根场景
 ├─ TileMap / 静态地形          ← 地板、墙、平台（色块占位）
 ├─ PartyManager (Node2D)       ← 角色队伍管理器（脊柱）
 │   ├─ Knight.tscn   (近战，初始激活)
 │   └─ Archer.tscn   (远程，初始休眠)
 ├─ Enemy.tscn        ← 1 个巡逻敌人
 ├─ PuzzleGate
 │   ├─ Switch        ← 远程角色射中才能触发
 │   └─ Door          ← 触发后打开
 ├─ Camera2D          ← 跟随当前激活角色
 └─ HUD (CanvasLayer) ← 当前角色 + 双角色血量
```

**核心流程**：Knight 开局 → 砍掉敌人 → 遇锁门，开关在近战够不到处 → 切换 Archer → 射中开关 → 门开 → 走到终点。

## 4. 角色系统（脊柱）

### 角色场景模板（Knight / Archer 同构，数值与行为不同）

```
Knight.tscn  (根: CharacterBody2D)
 ├─ Sprite          ← 贴图（色块占位）
 ├─ CollisionShape  ← 与地形碰撞
 ├─ Health          ← 可复用子节点：血量、受伤、死亡信号
 ├─ Hurtbox         ← 受击盒
 └─ StateMachine    ← 状态机：待机/移动/跳跃/攻击/受伤
```

- **Knight（近战）**：移动略慢、血厚；攻击为面前短距离挥砍判定（临时 Hitbox）。
- **Archer（远程）**：移动略快、血薄；攻击为发射 `Arrow.tscn`（飞行 + 命中），箭矢同时是解谜钥匙。

### PartyManager 切换逻辑（一次写好）

1. 持有角色列表 + 当前激活索引。
2. 按切换键 → 把新角色挪到当前角色位置（位置交接）。
3. 激活新角色：开启输入处理 + 显示；休眠旧角色：暂停处理 + 隐藏。
4. 通知相机跟随新角色，通知 HUD 更新。
5. **每个角色血量独立保存**，切回保持原血量。

> 取舍：休眠角色**留在场景但暂停**（不删除），视觉上隐藏。实现简单、状态保留。

## 5. 移动手感

用**状态机**管理角色行为状态。

| 状态 | 进入条件 | 行为 |
|------|---------|------|
| `Idle` | 地面、无输入 | 站立 |
| `Run` | 地面、有左右输入 | 水平移动 |
| `Jump` | 按跳跃且在地面 | 向上初速度 |
| `Fall` | 离地且竖直向下 | 受重力下落 |
| `Attack` | 按攻击键 | 出招，短暂锁住其他动作 |
| `Hurt` | 受击盒被命中 | 击退 + 硬直 + 无敌帧 |

**手感参数**（初值，后续调）：重力、最大水平速度、加/减速、跳跃初速度与最大高度。
**平台标配细节**：土狼时间（Coyote Time）、跳跃缓冲（Jump Buffer）。

**输入**：使用 Godot **Input Map**，动作名 `move_left` / `move_right` / `jump` / `attack` / `switch_character`。代码只认动作名，便于改键与加手柄。

## 6. 战斗（命中 / 受击 / 血量）

采用 **Hitbox / Hurtbox** 模式：

- **Hitbox**：攻击时产生的可打击区域（带伤害值）。
- **Hurtbox**：会被打到的区域。
- Hitbox 进入 Hurtbox → 触发伤害 → Hurtbox 通知其 `Health` 扣血。
- 「谁能打谁」由碰撞层（Collision Layer）控制：玩家攻击只命中敌人，敌人攻击只命中玩家。

**攻击**：
- Knight 近战：`Attack` 状态下面前短暂开启 Hitbox（挥砍）。
- Archer 远程：生成 `Arrow.tscn`（自带 Hitbox），沿朝向飞行，命中敌人或墙体消失。

**血量与死亡**（`Health` 子节点）：
- 记录当前/最大血量，受伤扣血，发出 `health_changed`、`died` 信号。
- 玩家死亡：**简单重生**（回房间起点、回满血），不做存档。
- 敌人：1 种，简单 AI（平台上来回巡逻，接触造成伤害）。做到「能被打、会打人、会死」。

**受击反馈**：受击闪白 + 轻微击退 + 短暂无敌帧。顿帧/粒子留到阶段 2。

## 7. 谜题设计（验证「必须切角色」）

```
PuzzleGate
 ├─ Switch  ← 放在近战够不到处（高处平台 / 深坑对面）
 └─ Door    ← 挡住通往终点的路
```

**解法逻辑**：
1. Knight 走到门前，门锁，过不去。
2. 开关在高处/远处，近战挥砍够不到。
3. 切换 Archer，射箭命中开关。
4. 开关 `Hurtbox` 被箭 `Hitbox` 命中 → 触发 → 发信号。
5. 门监听开关信号 → 打开（占位：下沉/消失）→ 放行。

**设计理由**：复用第 6 节 Hitbox/Hurtbox；只有箭能碰到开关（近战距离不够），自然强制用远程角色。开关→门用**信号连接**（松耦合），可扩展到多开关/多门组合，成为阶段 3 解谜系统的骨架。

> 取舍：开关触发后**永久开门**（最简，最易验证）。计时/重置类机关留到阶段 3。

## 8. 占位美术

阶段 0 **不碰真实美术**，全部色块/简单图形，逻辑与美术解耦（替换美术只改贴图，不动逻辑）。

| 对象 | 占位 |
|------|------|
| Knight | 蓝方块 |
| Archer | 绿方块 |
| 敌人 | 红方块 |
| 箭 | 小长条 |
| 开关 | 黄块（触发后变色） |
| 门 | 灰条 |
| 地形 | 深色块 |

## 9. 范围边界

### ✅ In Scope（阶段 0）
- 1 个测试房间（手摆地形）
- 2 角色（Knight 近战 / Archer 远程）+ 瞬间切换
- 基础移动（跑/跳/土狼时间/跳跃缓冲）+ 状态机
- 战斗：Hitbox/Hurtbox + 血量 + 1 巡逻敌人 + 受击基础反馈
- 1 个「必须切角色」的开关-门谜题
- 简单死亡重生 + 最简 HUD（当前角色 + 双角色血量）
- 全程占位美术

### ❌ Out of Scope（留给后续阶段）
- 存档/读档、房间切换、地图（阶段 1/4）
- 多敌人/复杂 AI/Boss/顿帧粒子（阶段 2）
- 多种机关/可复用解谜库（阶段 3）
- 真实美术/音效/剧情/菜单（阶段 5）
- 第 3 个及以后的角色（架构支持，阶段 0 只放 2 个）

## 10. 完成判定标准

能从房间起点出发 → 砍掉敌人 → 切角色射开关开门 → 走到终点；切换、战斗、解谜均正常工作，且**手感让人觉得「切角色玩法有意思」**。
